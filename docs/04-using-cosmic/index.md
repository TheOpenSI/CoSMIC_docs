## Chat Interface

**Using CoSMIC through chat.**

Send a question, and CoSMIC processes it and returns a response.

Each request carries your recent conversation history (the last 5 user/assistant pairs) along with the new question, so CoSMIC has short-term context for follow-up questions — see [Context Management](../core-concepts/context-management.md) for details and limits.

## Query Processing

**Following a request from start to finish.**

When a question is submitted, CoSMIC doesn't send it straight to a language model. It first classifies the request using the Query Analyser, then routes it to whichever service is built for that kind of task:

| If your question is about... | It's handled by... |
|---|---|
| A chess position or move | The Chess service (Stockfish) |
| Saving something to memory | The knowledge store |
| Writing or generating code | Code Generation |
| Anything else | General question answering, with document retrieval where relevant |

**Note:** "memory" here means writing text into the knowledge store for later retrieval — it's separate from the short-term conversation history CoSMIC already keeps automatically for follow-up questions.

This classification happens automatically for every message — see [Query Analysis & Service Routing](../core-concepts/query-routing.md) for how it works.

## Knowledge Retrieval (RAG)

**Adding and searching your own knowledge.**

CoSMIC can answer questions using documents you've added to its knowledge base, rather than relying only on what the language model already knows.

**Adding documents** — Upload a PDF, or provide text directly, and CoSMIC stores it for later retrieval. Documents are automatically checked for near-duplicate content before being added, so re-uploading the same file won't create duplicate entries.

There are two ways content gets added: direct upload, for your own conversation or account, and an automatic background process that picks up files shared more broadly. Only the second one runs without you doing anything.

**Querying documents** — Once added, relevant content is automatically retrieved and used as context whenever you ask a related question — no special syntax needed, this happens as part of normal chat.

**A note on relevance** — retrieval normally uses content that meets the configured relevance threshold. If no result meets that threshold, CoSMIC can retain the best available result rather than returning no context. If a document was added successfully but doesn't seem to be reflected well in an answer, it may be because the way the question was phrased didn't score as highly against the stored content as other candidates — see [Vector Databases](../core-concepts/vector-databases.md) and [Retrieval-Augmented Generation](../core-concepts/rag.md).

## Code Generation

**Generating code with CoSMIC.**

Asking CoSMIC to write or generate code routes the request to a dedicated code generation service — code isn't generated by the main chat model directly.

## Authentication

**Signing in to CoSMIC.**

CoSMIC uses single sign-on rather than its own username and password system. When you sign in, you're redirected to an identity provider — currently Google, with Microsoft and a self-hosted option also supported — to confirm who you are, then brought back into CoSMIC already signed in.

The first time you sign in with a given account, CoSMIC creates a profile for you automatically. There's no separate registration step — signing in for the first time and signing in again later use the same process.

### How it works

```
User
 │
 ▼
Click "Sign in"
 │
 ▼
CoSMIC redirects to your Identity Provider
(Google / Microsoft / other)
 │
 ▼
You sign in on that provider's page
 │
 ▼
Provider confirms your identity
 │
 ▼
CoSMIC creates a session (or finds your existing profile)
 │
 ▼
Returned to CoSMIC, signed in
```



Sign-in is handled by a dedicated part of CoSMIC DB, separate from the rest of the API. When you sign in, it takes you to your chosen identity provider, waits for confirmation, then sets up your session and sends you back to CoSMIC.

Your session is kept in a secure cookie rather than something you need to manage yourself. It renews automatically in the background, so you generally don't need to sign in again until the session genuinely expires.
